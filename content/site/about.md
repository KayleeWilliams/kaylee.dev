I'm a founding engineer at [Inth](https://inth.com) (YC P26) and co-author of [c15t](https://c15t.com), the open-source consent layer.

Consent tooling is usually the worst code on a page. It arrives as a third-party script the week before launch, slows the page down, and ignores the design system. c15t puts consent in your bundle and components. Teams review it with the rest of the code.

At Inth I'm building the rest of the compliance stack around the same idea. [DSAR](https://dsar-sdk.com) handles data-rights requests in code. [Cookiebench](https://cookiebench.com) measures the performance cost of consent tooling. [Leadtype](https://leadtype.dev) publishes docs for humans and agents from the same source. Compliance belongs in code.
